예비창업패키지 심사 기준에 맞춰 사업계획서를 검토하고 개선 피드백을 제공한다.

## Step 1: 프로젝트 파일 로드

워크스페이스에서 `bp-project.json`을 읽는다.
파일이 없으면: "먼저 `/new` 명령으로 예창패 프로젝트를 시작해 주세요."라고 안내하고 중단한다.

내용이 있는 섹션이 하나도 없으면: "아직 작성된 섹션이 없습니다. `/write`로 섹션을 작성한 후 검토해 주세요."라고 안내하고 중단한다.

선택된 주관기관 정보(`selected_host`)와 신청 분야(`application_category`)를 확인하여 해당 기관의 특화분야와 심사 특성을 반영한다.

## Step 2: 검토 범위 결정

$ARGUMENTS가 있으면 해당 섹션만 검토한다.
$ARGUMENTS가 없으면 내용이 있는 모든 섹션을 전체 검토한다.

## Step 3: 2025년 예창패 심사 기준 기반 섹션별 검토

`references/evaluation-criteria.md`를 참조한다.

2025년 공고 기준 평가 항목:
- **문제인식(30~40%):** 창업 아이템의 개발 배경 및 필요성, 시장성 검증
- **실현가능성(25~35%):** 창업 아이템의 사업기간 내 개발 또는 구체화 계획, 실행 가능성
- **성장전략(15~25%):** 창업 아이템의 사업화를 위한 차별성, 수익모델, 자금조달 방안, 중장기 성장성
- **팀(기업)구성(10~20%):** 대표자 및 고용(예정)인력이 보유한 기술 역량과 노하우

각 섹션에 대해 다음 형식으로 출력한다:

```
### [섹션명] — [점수]/5

**강점:**
- [잘 작성된 부분]

**개선 필요:**
- [보완할 부분 + 구체적 개선 방향]

**권장 추가 내용:**
- [심사에서 가점이 될 수 있는 요소]
```

섹션별 핵심 체크포인트:
- **일반현황 & 창업아이템 개요:** 한 문장으로 이해되는가? 고객-문제-솔루션이 명확한가? 산출물이 구체적이고 현실적인가?
- **문제인식:** 구체적 고객과 수치화된 피해가 있는가? 검증 근거(인터뷰/설문)가 있는가?
- **실현가능성:** 기술 나열이 아닌 결과 중심인가? 차별화가 명확한가? 마일스톤과 KPI가 구체적인가?
- **성장전략:** TAM→SAM→SOM 구조인가? 출처가 있는가? SOM이 현실적인가? ESG/사회적가치 고려가 있는가?
- **팀구성:** "왜 우리가"가 설득력 있는가? 아이템과 경험이 연결되는가? 어벤져스 팀 구성인가?

2025년 예창패 특화 체크:
- [ ] 기술 중심 서술("AI를 활용한" 식)이 없는가
- [ ] 경쟁사가 "없다"고 표현하지 않았는가
- [ ] 2025년 공고 요구사항을 모두 준수했는가
- [ ] 선택한 주관기관의 특화분야와 아이템 연관성이 잘 드러나는가
- [ ] 15페이지 제한(목차 제외)을 지켰는가
- [ ] 개인정보(주민등록번호, 계좌번호 등) 마스킹이 되어있는가

## Step 4: 2025년 예창패 종합 평가

```
## 2025년 예창패 심사 예상 평가

| 평가 항목 | 예상 평가 | 강도 |
|----------|---------|------|
| 문제인식 | [상/중/하] | 창업 필요성 명확성 |
| 실현가능성 | [상/중/하] | 실행 계획 구체성 및 현실성 |
| 성장전략 | [상/중/하] | 차별화·수익모델·시장성 |
| 팀(기업)구성 | [상/중/하] | 역량 보유 및 적합성 |
| **종합 평가** | **[상/중/하]** | |

**가점 (최대 3점):**
- [ ] AI대학원 출신 (2점)
- [ ] 창업경진대회 입상 (1점)
- [ ] 기후테크 분야 (1점)

**탈락 기준:**
- ⚠️ 60점 미만 탈락: 종합 점수가 60점 미만이 되지 않도록 주의하세요

**주관기관 특화분야 부합도:** [상/중/하] — [이유]

**우선 개선 항목 Top 3:**
1. [가장 시급한 항목]
2. [두 번째]
3. [세 번째]

**전체 흐름 평가:** [섹션 간 논리적 연결성, 메시지 일관성, 15페이지 준수]
```

## Step 5: 구체적 수정 예시 제공

가장 개선이 필요한 2~3개 항목에 대해 "수정 전 → 수정 후" 예시를 제공한다.

사용자가 원하면 `/write [섹션번호]`로 바로 수정할 수 있음을 안내한다.
전체 완성 후 `/export`로 Word/PDF 출력할 수 있음을 안내한다.
필요시 `/update [연도]`로 새로운 연도 자료로 업데이트할 수 있음을 안내한다.
